# LoRa 多场景信息采集系统

一主两从的 LoRa 组网，用于农田/温室/养殖等无市电、无网络的户外场景。终端节点用 RS485 读取土壤温湿度、氮磷钾、pH，通过 LoRa 定向帧回传给网关；网关汇总后经 4G DTU 上传 OneNET，实现远程可视化。

> 中国大学生计算机设计大赛 物联网应用类参赛作品（团队 5 人，本人任技术负责人）。
> 仓库包含 **三个 Keil 工程**：网关（`LoraZET6主节点移植`）+ 两个终端节点（`LoraC8T6副节点`、`LoraC8T6副节2本`）。

---

## 1. 系统概览

| 层级 | 组成 | 作用 |
| --- | --- | --- |
| 感知层 | STM32F103C8T6 + ATK-LORA-01 + RS485 传感器 | 采集土壤温湿度 / 氮 / 磷 / 钾 / pH，按命令回传 |
| 网络层 | STM32F103ZET6 + ATK-LORA-01 + 4G DTU | 轮询各节点、汇聚数据、协议转换、单点上云 |
| 应用层 | OneNET | 数据流存储、折线图 / 仪表盘可视化 |

**为什么节点用 LoRa、网关用 4G**：农田没有 Wi-Fi 覆盖，每点装 4G 卡成本过高；LoRa 自建网关即可覆盖整片地块，整网只保留 1 张 4G 卡。

| 方案 | 覆盖 | 功耗 | 成本 | 结论 |
| --- | --- | --- | --- | --- |
| Wi-Fi | 50–100 m | 高 | 低 | 不适合农田 |
| **LoRa** | 1–5 km（郊区） | 极低 | 中 | **本项目采用** |
| NB-IoT | 广域 | 低 | 每点一张卡 | 规模化后资费高 |
| 4G 直连 | 广域 | 高 | 高 | 成本与功耗不划算 |

## 4. LoRa 应用层协议

ATK-LORA-01 工作在**定向传输**模式时，串口前 3 字节被模块当作寻址头（高地址 + 低地址 + 信道），不进入对端缓冲区。因此 MCU 发出 10 字节，对端只收到 7 字节。

| 字节 | 网关发出（10 B） | 节点回传（10 B） |
| --- | --- | --- |
| 0 | 目标地址高字节 | 目标地址高字节（0x00） |
| 1 | 目标地址低字节（1 / 2） | 目标地址低字节（0x00） |
| 2 | 信道（23 = 0x17） | 信道（23） |
| 3 | 命令字（1 = 采集 A，2 = 采集 B） | 本机节点号（1 / 2） |
| 4–9 | 保留（0） | 湿度 H、温度 T、氮 N、磷 P、钾 K、pH |

网关收到 `[节点号, H, T, N, P, K, pH]`，用首字节区分来源。示例：

```
网关 → 节点 B : 00 02 17 02 00 00 00 00 00 00
节点 B → 网关 : 00 00 17 02 37 1B 6E 2B A0 43   // H=55 T=27 N=110 P=43 K=160 pH=67
```

> ⚠️ 该帧**没有 CRC 与长度字段**，空中误码无法识别，只能靠值域判断兜底。这是已知缺陷，改进方向见设计文档第 8 章。

## 5. 轮询时序

网关主循环 A/B 交替问询，每次问询后延时 500 ms 等应答：

```c
while (1) {
    LoRa_SendData(2, 23, 2);   // 问节点 B（地址 2，信道 23，命令 2）
    delay_ms(500);
    LoRa_ReceData();           // 收 B 的 7 字节
    LoRa_SendData(1, 23, 1);   // 问节点 A
    delay_ms(500);
    LoRa_ReceData();           // 收 A 的 7 字节
}
```

LoRa 是半双工，问询与应答必须串行；节点数增加后应把固定延时改为 AUX 中断 + 定时器超时。

## 6. 传感器（Modbus RTU）

三类传感器共用一条 RS485 半双工总线，靠从站地址区分：

| 传感器 | 从站 | 寄存器 | 问询帧（含 CRC） |
| --- | --- | --- | --- |
| 土壤温湿度 | 0x02 | 0x0000 × 2 | `02 03 00 00 00 02 C4 38` |
| 氮 / 磷 / 钾 | 0x01 | 0x001E / 0x001F / 0x0020 | `01 03 00 1E 00 01 E4 0C` 等 |
| 土壤 pH | 0x03 | 0x0000 | `03 03 00 00 00 01 85 E8` |

解析前先校验 `rx[0]` 是否等于从站地址，可挡住“地址冲突”和“上一帧残留”两类错值。
温度、湿度按 `((rx[5]<<8)|rx[6]) / 10.0` 解析（单位 0.1 ℃ / 0.1 %RH），氮磷钾与 pH 直接取 16 位整数。

## 7. 编译与烧录

1. 安装 **Keil MDK 5** + STM32F1 器件包；
2. 分别打开 `code/<工程>/Project/Lora_Project.uvprojx`；
3. 编译（F7），用 ST-Link（SWD）烧录；
4. 上电后串口 1（115200）打印初始化与收发日志。

三个工程需分别烧录到对应板子：网关 → ZET6，节点 A → C8T6（地址 1），节点 B → C8T6（地址 2）。

## 8. 已知问题与改进

**已知问题**
- 应用层无 CRC，误码只能靠值域兜底；
- 固定 500 ms 延时等应答，节点扩容后不适用；
- 温湿度取整后精度仅 1 ℃ / 1 %RH；
- 4G 断网期间数据直接丢弃，无补传；
- 网关的 FreeRTOS 多任务版本为设计目标，本仓库的主节点为裸机轮询版。

**改进优先级**
1. 数据帧追加 CRC16/MODBUS，网关校验失败即丢弃并重问；
2. AUX 中断 + 定时器超时替代固定延时；
3. 温湿度扩为 2 字节（帧长 10 → 16 B，仍在 LoRa 单包内）；
4. 网关用 Flash 环形缓冲做断网补传；
5. 节点定时唤醒 + 太阳能供电，把休眠电流压到 µA 级。
